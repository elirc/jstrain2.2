concepts: state → render · delegation · localStorage · exercises/20-todo-app.html

Everything at once. One array of state, one render function, one listener per container.

State — an array of { id, text, done } plus the current filter ('all' / 'active' / 'done'). Ids only need to be unique.

Render — clear #todo-list, then one row per visible todo:

<li class="todo" data-id="1"><input type="checkbox" class="toggle"><span class="text">…</span><button class="delete">✕</button></li>

  • a done todo: the <li> also has the class done and its checkbox is checked
  • #todo-count reads 2 left — todos that are not done, whatever the filter is showing
  • the current filter button carries the class active

Behaviour

  • submitting the form adds the trimmed text (empty → nothing at all), clears the input, and never reloads the page
  • the checkbox toggles done; the .delete button removes that todo — both through one delegated listener on #todo-list (checkbox → the change event)
  • the filter buttons switch what is rendered (nothing is deleted)
  • #clear-done drops every done todo
  • everything is saved to localStorage under dom.todos and reloaded by setup(), inside try/catch

hint: change the array, save, call render(). Never edit a row in place — rebuilding the list from state is what keeps six features from contradicting each other. Find the todo a click belongs to with Number(event.target.closest('.todo').dataset.id).
