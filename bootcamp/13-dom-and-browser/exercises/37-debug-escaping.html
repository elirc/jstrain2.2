This page is a bug hunt. A comment list renders whatever visitors typed. Comments are plain text: whatever a visitor types must appear on screen character for character, and must never become part of the page's markup.

It renders fine for ordinary comments. Then a visitor posted one containing angle brackets, and support started getting reports of a popup on the article page. Find the one bug and fix it with the smallest change. Don't rewrite render().

hint: two properties on an element can put a string on the screen. One of them asks the HTML parser to read it first. Which one is in use, and what does the parser do with <img src=x onerror=...>?
