34 · A board that remembers — SOLUTION ★★★ stretch

concepts: one state object · projection into columns · JSON in storage · solutions/34-mini-kanban.html

The finale: three columns, cards that move between them with buttons, and a board that is still there after a reload.

  • the state is one object, id → column. Every card starts in COLUMNS[0]
  • render each card into its column as <li class="card" data-id="c1"> with a .title and two buttons carrying data-move="left" / "right". Inside a column cards keep their CARDS order, so one that moves out and comes back lands where it started
  • left in the first column and right in the last are disabled
  • each column's .count shows how many cards it holds, and #board-state reads todo 2 · doing 1 · done 0
  • every move saves the state as JSON under BOARD_KEY, and setup restores it — junk, a missing key or a card parked in a column that no longer exists all fall back to the default board

hint: JSON.parse throws on anything that is not JSON, so it belongs inside the same try/catch as the read — and valid JSON is still not valid data. Check each saved value against COLUMNS before you trust it. Render by filtering CARDS per column, so a card can only ever be in one place.
